# Промпт для локальной сессии: перемер задач в «Анализе по шагам»

Скопируйте всё, что ниже линии, в ту же сессию Claude Code, где делали `bench-report/analysis-chain.md`.

---

Ты работаешь на моём Windows-ПК с Verbaliox (RTX 3090). По разделу «Перемер после правок» в
`bench-report/analysis-chain.md` в ветке `claude/sweet-maxwell-uaextf` сделаны правки. Проверь главное: находит ли
«Анализ по шагам» задачи не хуже обычного режима. Отвечай мне по-русски.

## Правила

Те же, что в прошлый раз:
- копии данных и моделей через `VERBALIOX_DATA_DIR` и `VERBALIOX_MODELS_DIR`;
- без релиза, коммиты только в свою ветку;
- только `gemma4:e4b`, контекст 32k;
- без имён из моих записей.

## Что изменилось

1. `225025c` — по шагам задачи ищутся без подсказок-решений (`hints=""`). При ручном пересчёте задач решения
   протокола даются как дополнение: «сначала найди задачи по всей расшифровке, как обычно, затем проверь пункты
   ниже».
2. `9100a80` — протокол по шагам проверяется по расшифровке (`maybe_ground`) до вставки решений и задач.
   Вставленные строки «[?]» больше не получают.
3. `30805f3`:
   - в промпте шага 1 — не инструкции и не описание процесса, на любом языке;
   - лимит ответа при контексте 32k — 6144 токена (раньше 3072).

## Что сделать

1. `git fetch && git checkout claude/sweet-maxwell-uaextf && git pull`. Тесты — код возврата 0.
2. **Задачи.** `tools/llm_bench.py --app-flow` и `--chain` на тех же 8 записях, каждый режим дважды, судья
   `tools/llm_judge_tasks.py`. Сравни полноту и точность. Цель — по шагам не хуже обычного (в прошлый раз 0,39 /
   0,84 против 0,20 / 0,68).
3. **Ручной пересчёт задач** при готовом протоколе (обычный режим). На записях 84, 85 и 4, по три раза, сравни
   с подсказками в новой формулировке (`note_for_tasks`) и без них (`hints=""`). Если с подсказками полнота снова
   ниже, напиши об этом прямо.
4. **Попутно, по тем же прогонам:**
   - **обрывы:** сколько раз в логе `the answer was cut … asked again` и время на часовую запись;
   - **запись 4:** сколько решений по шагам (было 7 и 16) и есть ли «[?]» в «Следующих шагах»;
   - **расхождения:** протокола и задач до и после синхронизации.

## Отчёт

Допиши в `bench-report/analysis-chain.md` раздел «Перемер задач» и запушь в свою ветку. Сырые результаты — с
суффиксом `-v3`. Пришли мне коротко:
- таблицу «было → стало» по задачам в обоих режимах;
- обрывы и время;
- вывод: можно ли выпускать с «Анализом по шагам» по умолчанию.
