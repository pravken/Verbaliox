# Промпт для локальной сессии: проверка 0.8.7-beta.2 на ПК

Скопируйте всё, что ниже линии, в сессию Claude Code на компьютере с Verbaliox. Подойдёт сессия, где уже
проверяли модели и видеокарту: клон и копия базы там есть.

---

Ты работаешь на моём Windows-ПК с Verbaliox (RTX 3090). Вышла бета `v0.8.7-beta.2` (ветка
`claude/sweet-maxwell-uaextf` влита в `main`). Облачная сессия проверила её тестами и в браузере, но без
видеокарты, без Windows, без моих записей и без ключей облачных API. Проверь то, что можно только здесь.
Отвечай мне по-русски.

## Правила

- Не трогай мою настоящую папку данных (`%LOCALAPPDATA%\Verbaliox`) и мои модели (`<папка программы>\models`).
  Работай с копиями через `VERBALIOX_DATA_DIR` и `VERBALIOX_MODELS_DIR` во временных папках.
- Ключи API не пиши в чат, файлы и коммиты. Ключ я вставлю сам в «Настройки → Анализ» запущенной копии.
- Релиз не выпускай. Коммить только в свою ветку от `main`, одна тема на коммит. Перед пушем — зелёные
  тесты и просмотр своего диффа.
- Модели и пакеты — только бесплатные и разрешённые для коммерции. Если лицензия меняется, остановись и
  спроси меня.
- Каждый платный облачный запрос — с моего согласия. Перед прогоном скажи, сколько примерно он будет
  стоить.

## 0. Подготовка

1. В клоне `Verbaliox-bench`: `git fetch && git checkout main && git pull`. Убедись, что
   `app/__init__.py` даёт `0.8.7-beta.2`.
2. `PY` — это `<папка программы>\.venv\Scripts\python.exe`. Свежая копия `%LOCALAPPDATA%\Verbaliox` лежит
   в `%TEMP%\vs-b2-data`, модели — в `%TEMP%\vs-b2-models`. Модели можно скопировать из моих, чтобы не
   качать заново.
3. Запусти тесты: `PY -m unittest discover -s tests -t .`. На Windows должны пройти все.
4. Миграция старой базы. Запусти сервер на копии и открой фичи, задачи и MFU. Проверь, что в таблице
   `features` появились столбцы `description`, `keywords`, `terms`, а в `meetings` — столбец `mfu`. Ошибок
   в логе быть не должно.

## 1. Облачный анализ с настоящими ключами

Изменено в `app/llm.py`:
- Claude больше не получает `temperature` и получает `max_tokens` 16000.
- Отказ (`refusal`) и обрезка — это ошибки.
- OpenAI повторяет запрос без `temperature`, если модель её не принимает.
- Gemini: любой `finishReason`, кроме `STOP`, — ошибка.
- Снятая модель (404) заменяется на модель того же семейства.
- Каждая отправка пишется в журнал облачных запросов.

Для каждого провайдера, ключ которого я дам (Anthropic, OpenAI, Gemini):

1. «Проверить подключение» в «Настройки → Анализ»: ответ без ошибки 400.
2. Протокол и задачи по одной записи на 60–90 минут. Модели:
   - Claude: Haiku 5.5, Sonnet 5.5, Opus 5.5;
   - OpenAI: модель по умолчанию и одна модель gpt-5 / o-серии;
   - Gemini: Flash.

   Для каждой запиши время, длину протокола, число задач, была ли ошибка.
3. **Лимит Claude.** У Opus 5.5 и Sonnet 5.5 рассуждение всегда включено и делит 16000 токенов с ответом.
   Посмотри, обрезается ли длинный протокол: тогда будет ошибка «ответ модели обрезан». Если да,
   предложи решение и не коммить без меня. Варианты:
   - `output_config: {"effort": "medium"}`;
   - потоковый ответ с большим лимитом.
4. **Снятая модель.** Впиши в настройку модели несуществующее имя той же линейки (например,
   `claude-haiku-0`). Запусти анализ и проверь:
   - модель заменилась на Haiku, а не на Sonnet;
   - настройка обновилась;
   - в журнале облачных запросов две записи с фактическими моделями.
5. **Журнал.** Число записей равно числу отправок, имена моделей верные.
6. **Gemini и `temperature 0.2`.** Проверь, не зацикливаются ли новые модели Gemini (повторы строк в
   протоколе). Если зацикливаются, предложи `temperature` по умолчанию для Gemini.
7. **Стоимость.** Сколько стоила одна встреча у каждой модели: по консоли провайдера или по `usage` в
   ответе.

## 2. Контекст Ollama после глоссария и описания фичи

В запрос протокола и задач теперь добавляются:
- глоссарий словаря (до 80 терминов);
- описание фичи (до 2000 знаков);
- MFU (до 6000 знаков).

Бюджет расшифровки при этом не уменьшился.

1. Создай фичу с описанием на 2000 знаков и 80 терминами. Повесь её на запись на 60+ минут и вставь MFU
   на 6000 знаков.
2. Запусти протокол и задачи на `gemma4:e4b`: с контекстом 32k (видеокарта 8 ГБ и больше) и с профилем
   16k (`tools/vram_ballast.py` или `--ctx 16384` в `tools/llm_bench.py`).
3. По логу Ollama и `prompt_eval_count` проверь, помещается ли запрос вместе с ответом в `num_ctx`, в том
   числе при повторе с `num_predict` 8192. Если Ollama обрезает начало запроса (`truncating input`),
   предложи уменьшать бюджет расшифровки на размер добавок.

## 3. Качество задач после правок

Изменено в `app/commitments.py` и `app/people.py`:
- фильтр «действие на встрече» стал уже: документ, файл, «сейчас пришлю» теперь остаются задачами;
- сопоставление имён строже: каждое сказанное слово должно подходить участнику;
- похожие задачи с задачами из MFU склеиваются строже.

1. Запусти `tools/llm_bench.py` и `tools/llm_judge_tasks.py` на 8 эталонных записях с `gemma4:e4b`.
   Сравни полноту и точность с прошлым прогоном (`bench-report/llm-profiles.md`). Мусорных «пошарю экран»
   не должно стать заметно больше.
2. На моих записях Teams проверь, что «Макс» по-прежнему становится «Maksim Pravko». Найди случаи, где
   исполнитель остался «как сказано», хотя человек есть среди участников, и пришли мне примеры.

## 4. Nemotron 3 Diarization на видеокарте

1. Поставь Nemotron в «Настройки → Распознавание» в копии моделей и проверь, что рядом с моделью лежит
   файл лицензии.
2. Прогони 3–4 моих записи:
   - в режиме «Авто»;
   - с заданным числом участников.

   Сравни с ECAPA по `tools/diar_bench.py`: доля ошибок, время, пик видеопамяти.
3. Проверь bf16 на CUDA: быстрее ли и не хуже ли по ошибкам. Проверь переход на процессор, если
   видеокарта занята (например, LLM).

## 5. Интерфейс в окне программы (WebView2)

1. **Фичи.**
   - Создай 3–4 фичи, задай свой цвет и описание.
   - Правило серии: новая встреча серии получает фичу сама.
   - Название встречи в Teams даёт подсказку ✓ / ✕.
   - Фильтр и группировка в медиатеке и на странице «Задачи».
2. **Страница фичи.**
   - Раздел «Решения» заполняется у протокола, созданного заново. У старых протоколов он пуст: так и
     должно быть.
   - Отметка задачи сразу меняет счётчики.
   - Esc закрывает страницу.
   - Кнопка ↗ в выборе фичи работает с клавиатуры (Tab, Enter).
3. **Карточки задач.**
   - Метки MFU / LLM / ✎ стоят на одном месте у всех карточек.
   - Клик по исполнителю и сроку открывает их списки.
   - Карточки умещаются в узком окне.
4. **MFU.** Вставь итоги из чата Teams и переключись на другую запись и обратно: текст не теряется и не
   попадает в чужую запись.

## 6. Обновление из программы

1. На копии с установленной `0.8.7-beta.1` и включённым «Получать бета-версии» обнови программу.
   Проверь:
   - скачалась `0.8.7-beta.2`;
   - подпись проверилась;
   - после перезапуска версия новая, данные на месте.
2. Установщик `Verbaliox-Installer-v0.8.7-beta.2.exe` на чистой папке: проверь первый запуск и выбор
   модели по видеокарте (Gemma 4 E4B на 3090).
