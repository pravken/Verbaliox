# Промпт для локальной сессии: замер «Анализа по шагам»

Скопируйте всё, что ниже линии, в сессию Claude Code на компьютере с Verbaliox. Подойдёт сессия, где уже
гоняли `tools/llm_bench.py` и `tools/llm_judge_tasks.py`: клон, копия базы и эталонные записи там есть.

---

Ты работаешь на моём Windows-ПК с Verbaliox (RTX 3090). В ветке `claude/sweet-maxwell-uaextf` появилась
настройка «Анализ по шагам» («Настройки → ИИ-анализ», ключ `analysis_chain`, по умолчанию выключена). Нужно
понять, делать ли её основной. Отвечай мне по-русски.

## Правила

- Не трогай мою настоящую папку данных (`%LOCALAPPDATA%\Verbaliox`) и мои модели (`<папка программы>\models`).
  Работай с копиями через `VERBALIOX_DATA_DIR` и `VERBALIOX_MODELS_DIR` во временных папках.
- Релиз не выпускай. Коммить только в свою ветку от `claude/sweet-maxwell-uaextf`, одна тема на коммит.
  Перед пушем — зелёные тесты и просмотр своего диффа.
- Облачные модели не используй: замер только на локальной `gemma4:e4b`.
- В отчёт, логи и `bench-report/` не переноси имена из моих записей: пиши «участник 1», «организатор»,
  «исполнитель».

## Что изменилось

Без настройки протокол делается одним запросом, а задачи — отдельным.

С настройкой (`app/analysis_chain.py`) три шага:
1. Решения и открытые вопросы — шаблон `decisions`.
2. Задачи — `commitments.extract` с этими решениями как подсказками.
3. Протокол — с готовыми решениями и задачами. Разделы «Решения», «Открытые вопросы» и «Следующие шаги»
   программа потом переписывает списками из шагов 1 и 2.

В обоих режимах задача, которой нет в «Следующих шагах» протокола, дописывается туда после поиска задач
(`sync_next_steps`).

## 1. Подготовка

1. `git fetch && git checkout claude/sweet-maxwell-uaextf && git pull`.
2. Тесты: `PY -m unittest discover -s tests -t .` — все зелёные.
3. Копия базы с 8 эталонными записями (те же, что в `bench-report/llm-profiles.md`).

## 2. Замер

Для каждой из 8 записей, на `gemma4:e4b` с контекстом 32k, сделай два прогона: настройка выключена и
настройка включена. Если в `tools/llm_bench.py` нет режима цепочки, добавь флаг `--chain`, который вызывает
`analysis_chain.run`. Для каждой записи и каждого режима запиши:

- **время:** общее и по шагам;
- **задачи:** полнота и точность по `tools/llm_judge_tasks.py` против эталона;
- **решения:** сколько решений в протоколе и сколько из них подтверждаются расшифровкой (по таймкодам);
- **рассогласование:**
  - сколько задач нет в «Следующих шагах» протокола;
  - сколько шагов протокола нет среди задач;
  - сколько решений-действий не стали задачами.

  В режиме по шагам первые два числа должны быть 0;
- **качество текста:** «Краткое содержание» и «Обсуждение по темам» — прочитай 2–3 записи сам. Не стали ли
  они беднее, если модель знает итоги заранее?

## 3. Отчёт

Положи отчёт в `bench-report/analysis-chain.md` и запушь в свою ветку. Пришли мне его коротко:

- таблица по записям: режим | время | задачи (полнота / точность) | решения | рассогласования;
- вывод: делать ли «Анализ по шагам» основным, и что поправить в промптах шага 1 или 3, если качество хуже;
- если рассогласования остаются и в режиме по шагам — примеры (без имён) и где в коде их причина.
