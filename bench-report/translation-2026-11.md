# Перевод живых субтитров en↔ru: модели для «Качество» и «Скорость» (2026-11-24)

**Вывод.**
- **«Качество»: Hy-MT3-7B (Apache-2.0).** Лучший результат в обе стороны по chrF++ и наравне с лучшими по
  COMET; помещается в карту 10 ГБ вместе с GigaAM с запасом ~4 ГБ; медиана 0,21–0,40 с на строку, p90 ≤0,74 с —
  укладывается в требование субтитров (медиана ≲0,5 с, p90 ≲1 с). gemma4:e4b (сейчас) — на 1–2 пункта chrF++
  ниже en→ru/ru→en и заметно ниже по COMET en→ru, но быстрее.
- **«Скорость»: Hy-MT3-1.8B (Apache-2.0).** Лучше gemma4:e2b (сейчас) по COMET en→ru (0,813–0,819 против
  0,783) и не хуже по chrF++, при этом быстрее (медиана 0,10–0,16 с) и меньше (1,3 ГБ на диске против 4,4).
- **Но обе модели Hy-MT3 нельзя просто добавить в список моделей.** GGUF-репозиторий Hy-MT3-1.8B под Ollama
  0.40.8 приходит со сломанным шаблоном чата (модель не получает текст и отвечает бессмыслицей, chrF++ 1,6),
  а переводят обе модели только с промптом со своей карточки, не с промптом субтитров. См. «Что нужно для
  перехода».
- TranslateGemma 12B по качеству рядом с Hy-MT3-7B, но медленнее (p90 до 0,76 с), впритык помещается в 10 ГБ
  (свободно ~0,5 ГБ) и выходит под Gemma Terms of Use, не Apache — без решения автора не брать.
- Opus-MT самый быстрый (0,05–0,07 с), но сильно слабее всех (COMET 0,70–0,75): не годится.

## Условия

- Скрипт `tools/bench_translate.py`, ветка `claude/sweet-maxwell-uaextf` (коммит 288a412).
- Данные: WMT24++ (`google/wmt24pp`, en-ru_RU, Apache-2.0), 100 строк по 5–30 слов (соцсети 55%, литература
  22%, новости 20%, речь 3%), фиксированный seed. ru→en — те же пары наоборот: русская сторона сама перевод,
  поэтому это направление легче настоящей русской речи.
- Каждая строка переводится отдельно, как в субтитрах. gemma4 — кодом субтитров (`LiveTranslator._translate_clean`:
  промпт, параметры, очистка, повторы); TranslateGemma и Hy-MT — промптом с карточки модели; `@app` — промпт
  субтитров. Контекст 2048 (как у субтитров).
- RTX 3090 24 ГБ, процессор AMD (32 потока), Windows; Ollama 0.40.8; Opus-MT — CTranslate2 int8 на видеокарте.
  Программа на время замера закрыта. Время — этого ПК под его нагрузкой: сравнивать модели между собой.
- Карта 10 ГБ изображалась `tools/vram_ballast.py --card 10 --asr`: балласт 12,25 ГБ + GigaAM v3 на CUDA
  (1,39 ГБ, копия модели во временной папке), свободно по NVML 8,07 ГБ — как на 10-гигабайтной карте во время записи.
- COMET: `Unbabel/wmt22-comet-da` в отдельном окружении (на процессоре).

## Что нужно для перехода на Hy-MT3 (код программы, не этот коммит)

1. **Шаблон Hy-MT3-1.8B.** `ollama pull hf.co/tencent/Hy-MT3-1.8B-GGUF:Q4_K_M` (Ollama 0.40.8) даёт шаблон без
   `{{ .Prompt }}` и с обрывком `onse }}` вместо `{{ .Response }}`. Для замера модель пересоздана через
   `/api/create` (тот же GGUF) с шаблоном из `chat_template.jinja` репозитория `tencent/Hy-MT3-1.8B`:
   ```
   {{ if .System }}<｜hy_begin▁of▁sentence｜>{{ .System }}<｜hy_place▁holder▁no▁3｜>{{ else }}<｜hy_begin▁of▁sentence｜>{{ end }}<｜hy_User｜>{{ .Prompt }}<｜hy_Assistant｜>{{ .Response }}<｜hy_place▁holder▁no▁2｜>
   ```
   stop: `<｜hy_place▁holder▁no▁2｜>`, `<｜hy_place▁holder▁no▁8｜>` (у GGUF `add_bos_token = false`, BOS ставит
   шаблон). Программе нужно так же создавать модель с этим шаблоном при установке (или проверять шаблон и
   чинить). Шаблон Hy-MT3-7B из GGUF-репозитория правильный (`<|startoftext|>…<|extra_0|>`).
2. **Промпт с карточки.** Hy-MT переводит одним сообщением пользователя по шаблону карточки и параметрами
   генерации карточки (temperature 0,7, top_k 20, top_p 0,8, repetition_penalty 1,05) — как
   `native_translator` в `tools/bench_translate.py`. `LiveTranslator` сейчас отправляет всем моделям промпт
   субтитров; для Hy-MT нужна своя ветка (по образцу скрипта).
3. **Отдельная модель перевода.** Сейчас «Качество» субтитров — это модель анализа (`ollama_model`), а
   «Скорость» — первая установленная из `FAST_MODEL_HINTS`. Hy-MT3 — только переводчик, анализ на нём не
   сделать: для «Качество» нужна отдельная настройка модели перевода, иначе в 10 ГБ придётся держать и
   gemma4:e4b для анализа, и Hy-MT3-7B для перевода.
4. **README:** Hy-MT3 (Apache-2.0, Tencent) — в таблицу лицензий.

Поэтому `FAST_MODEL_HINTS` и рекомендация модели в `app/hardware.py` в этом коммите не меняются: строка
`hf.co/tencent/Hy-MT3-1.8B-GGUF:Q4_K_M` в подсказках включила бы модель со сломанным шаблоном.

## Оговорки

- 100 строк — разброс chrF++ между соседними моделями (1–2 пункта) сопоставим с погрешностью; COMET и chrF++
  местами расходятся (translategemma:4b: низкий chrF++, высокий COMET). Порядок «Hy-MT3-7B ≥ e4b» и
  «Hy-MT3-1.8B ≥ e2b» держится по обеим метрикам.
- ru→en — обратный перевод с переведённой русской стороны; на настоящей русской речи (оговорки, слова-паразиты)
  цифры будут ниже у всех.
- Время — одной видеокарты под нагрузкой этого ПК; на RTX 3080 будет медленнее, но соотношение моделей то же.

Сырые результаты: `translation-2026-11/results-full.{md,json}` (вся карта),
`translation-2026-11/results-10gb.{md,json}` (10 ГБ с GigaAM) — все переводы, оценки и настройки.
